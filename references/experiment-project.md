# 实验项目规范

使用可维护的本地项目结构。每一次实验都必须可追溯。

## 必需目录

```text
experiment/
├── configs/
├── data/
├── src/
├── scripts/
├── results/
│   ├── raw/
│   └── processed/
├── figures/
└── logs/
```

## 必需运行元数据

每次实验运行都必须记录：

- 实验编号
- 日期和时间
- Git 提交号或代码快照说明
- 数据集版本
- 配置文件路径
- 随机种子
- 硬件和运行环境说明
- 原始输出路径
- 处理后结果路径
- 如生成图表，记录图表路径
- 已知异常

## 数据检查

每批结果产生后：

- 对结果文件运行 `scripts/check_stat.py`。
- 存在多随机种子结果时运行 `scripts/check_seed_stability.py`。
- 如果有公开报告值，比较基线复现结果和报告值。
- 将异常记录到 `stage/3-experiment-run/artifacts/anomaly-report.md`。
- 对论文会使用的结果生成汇总表、验证报告和结果审计报告；不要只依赖控制台输出。
- 如果后续写作发现实验支撑不足，先回退到实验设计或实验运行阶段，补充 baseline、敏感性、消融或约束检查。
- 论文中的每个关键数值必须能追溯到配置文件、结果文件、图表文件或审计报告。

## Profile 选择

初始化项目时用 `--profile` 选择论文类型，关卡检查会据此改变 Stage 3 要求：

- `simulation`：仿真论文，重点检查约束可行性、功率/质量/安全边界和结果审计。
- `ml-experiment`：机器学习实验论文，重点检查多随机种子、统计检验和基线复现。
- `engineering-design`：工程设计论文，重点检查约束、参数扫描和设计权衡。
- `review`：综述或调研论文，重点检查证据表、来源质量和引用覆盖。
- `generic`：默认通用论文，保留统计检验目录要求。

## 图表检查

进入阶段 4 前，图表应达到可投稿状态：

- 字体清晰，字号一致。
- 优先导出矢量格式（`.pdf`、`.svg`），否则使用高分辨率位图。
- 坐标轴标签、图例和标题与论文术语保持一致。
- 定量图表不要使用截图。
- 架构图必须表达系统逻辑，而不只是堆方框：区分能量流、控制流、传感反馈和部件层级。
- 对单栏/双栏目标宽度做图像尺寸检查，避免文字出框、重叠、被裁切或压缩后不可读。
